Experiment 4 of 4 · alignment

Getting stuck in the wrong answer

To train a robot on a generated world, the world has to be lined up with what the robot really sees. Registration methods like ICP slide downhill and stop in the first valley, which can be the wrong one. Full-waveform inversion calls this cycle skipping, and optimal-transport misfits were introduced to avoid it.

What you will learn

Why aligning generated and real geometry can get stuck (cycle skipping), and whether optimal transport helps.

Key takeaway

One optimal-transport formulation looked far worse than ICP, but it had a tenth of the update budget; at matched compute the two are about level (inconclusive). Point-to-plane ICP did better, a classical result.

Cycle skipping in one dimension

The "data" are a pattern of narrow bumps and a shifted copy. The plot shows how much each misfit changes as the shift grows. A local optimiser follows the curve downhill, so the number of valleys is the number of places it can get stuck. Narrow features make the L2 curve ripple; the optimal-transport curve stays one smooth bowl.

Why this matters for geometryRegistering a generated world to real data has the same structure: a wrong starting scale, rotation or offset, and a misfit with many local minima. A Wasserstein misfit compares where the mass is, so it gives a useful pull even when the two clouds barely overlap.

The experiment

Question

Does an optimal-transport misfit give a convergence basin at least 1.5× as wide as trimmed ICP when aligning a generated world to reference geometry, under errors in scale, rotation and translation?

Design (pre-specified)

12 synthetic-truth cases; world held out for tuning, 8 cases for evaluation. Perturbation levels up to 2× the proposal's "scale ±40%, rotation 30°, translation 1 unit", five draws per level. Methods: trimmed ICP, point-to-plane ICP, unbalanced entropic OT, an OT→ICP hybrid, and FPFH+RANSAC as a reference. Success: aligned within a quarter of the tolerance. Basin = the largest perturbation at which every draw succeeds.

Read this first: the result changed after a self-checkAs first run, optimal transport had 10 similarity updates against ICP's 100, and it looked much worse. A post-hoc rerun with matched compute (100 updates each) found the two about level, with an inconclusive comparison. The earlier negative verdict was largely a compute artefact. Result: the success criterion is not met, and the first negative result was largely a compute artefact.
Caveats stated before the run
  • In the main variants the "reference" is itself an ICP solution, so ICP has a built-in advantage. A third variant uses an exact known transform to remove that circularity and is trusted more if they disagree.
  • The generator is a stand-in, not Marble; real generator output would have different statistics for the parts it fills in.
  • The OT inputs are subsampled, so its final accuracy is coarser than ICP's. The OT→ICP hybrid is reported to separate basin width from final accuracy.
